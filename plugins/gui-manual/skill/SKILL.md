# GUI 功能手册（AI 查询指南）

这是**这个 GUI 客户端自己**的功能手册 —— 用户界面上能看到的每一样东西，以及怎么用。

## 什么时候查

| 用户在说 | 你该做 |
|---|---|
| 「XX 在哪」「怎么打开 XX」 | 查对应章节 → 给出**准确路径**（哪个按钮/菜单/快捷键） |
| 「怎么用 XX」「XX 怎么设置」 | 查对应章节 → 给出**照着能做的步骤** |
| 「我不会用这个软件」「有什么功能」 | 先给功能概览（按章节），再按他关心方向深入 |
| 「为什么 XX 不生效」「XX 没反应」 | 查该功能**是否有前置条件**（如"要先绑定工作区""开关默认关着"） |
| 你要说「去设置里改…」之前 | **先核对**菜单路径 —— 别凭印象（这个 GUI 的设置项一直在变） |

⚠️ 手册**只覆盖 GUI 自身功能**。插件带来的能力（截屏、操作鼠标键盘、浏览器自动化）另见那些插件自己的技能/文档；手册里提到时会标注「取决于装了哪个插件」。

## 怎么查（三步）

1. 看下面的**章节索引**，找出最可能的一两章
2. 读那个章节文件（路径形如 `<本技能目录>/chapters/NN-xxx.md`，每次约 1K tokens，很便宜）
3. 按下面的「回答姿势」组织回答

**拿不准是哪章时**：宁可多读一章（1K tokens）也别瞎猜 —— 猜错会害用户在一个不存在的地方找半天。

## 回答姿势（重要）

**① 用用户视角的词，别用实现术语**

手册里写的是界面上的文字，照它说：
- ✅「设置 → 聊天 → 「Enter 键」那一项」
- ❌「改 `chatEnterBehavior` 设置」

**② 给"照着能做"的路径**

按钮叫什么叫什么、在哪个位置（"工具栏最左边三个按钮""标签右键菜单里"）、有没有前置条件（"要先绑定工作区"）。涉及快捷键的，提醒可以去 设置 → 快捷键 改。

**③ 手册没有的，如实说**

用户问的功能手册里没有 → 直说「手册没覆盖这个」，**别编一个路径**。
如果他的问题其实是 GUI 用错了而不只是「不会用」（像是 bug），告诉他可以走 **应用菜单 → 反馈** 提。

**④ 能顺手做的事就做掉**

如果用户的问题可以**一步到位**（比如"打开帮助面板看看"→ 你可以直接 `@ref{panel:help}`），
就别只丢一句话让他自己找 —— 给指引 + 给链接（`@ref{panel:<id>}`）效果最好。
