# pointer —— 屏幕教鞭

在用户屏幕上画**箭头 / 方框 / 圆圈 / 文字标签**，指给他「点这里」。

> **透明 + 点击穿透**：不挡用户操作，`duration` 秒后自动消失。
> 工具名：`plugin_pointer_point`（还有 `clear: true` 用于提前清除）。

## 什么时候用

**用户问「XX 在哪」「怎么点」「我不会用」** → **画给他看**，别只用文字描述。

```
✗ "点击右上角的齿轮图标"
   → 用户还得自己找"右上角"和"齿轮图标"

✓ 截图定位 → 在那个齿轮上画个圈 + 标签 "1"
   → 一目了然
```

## 标准闭环（三步，别跳）

1. **查**：`gui-manual` 技能 —— 知道功能在哪个面板/菜单（用户问的是 GUI 功能时）
2. **看**：`plugin_screenshot_fullscreen` / `plugin_screenshot_region` —— 定位目标的**实际屏幕坐标**
3. **指**：`plugin_pointer_point` —— 画出来

**第 2 步不能省。** 凭印象给的坐标几乎肯定是错的（窗口可能被移动过、分辨率变了、
布局和你想的不一样）。

## 坐标

**要传的是「屏幕绝对物理像素」** —— 和 `mouse-keyboard` 同一个空间。

**换算公式不在本文档** —— 见 **`computer-use` 技能的 `references/coordinates.md`**
（那里是坐标换算的**单一来源**：公式、多屏、DPI 陷阱、自检清单都在那）。

> 为什么写指针：**换算逻辑只维护一份**。以前同一件事散在 MCP 描述 / AI_NOTES /
> render.py 注释 / 技能四处，已经漂移出过互相矛盾的说法（AI_NOTES 曾写错"要减
> monitorOrigin"）。**改算法时只改 `coordinates.md` 一处。**

这里只给**最容易踩的三条**：

- ❌ **别用外部工具（PowerShell/.NET）量坐标** —— 它们 DPI unaware，
  读到的是**逻辑像素**，系统性偏差。用截图量，或让被测窗口自己报告。
- ❌ **别把图内像素当物理像素** —— 大屏全屏图会被降采样。
- ✅ **自查**：坐标超出虚拟桌面尺寸 = 多半算错了。

> ⚠️ **别用外部工具（PowerShell/.NET）量坐标** —— 它们是 DPI unaware，
> 读到的是**逻辑像素**（÷缩放比），会系统性偏差。详见 `computer-use` 技能。

## 关键参数

| 参数 | 说明 |
|---|---|
| `duration` | 停留秒数（默认 8；**0 = 不自动消失**，适合"等你照着做完"的多步操作） |
| `dim` | 默认 true = 压暗全屏、只留亮指示区域。**指"你要读的文字"时设 false**（压暗会看不清） |
| `monitor` | 画在哪块屏（默认主屏）。用截图的 `meta.monitorIndex` |
| `clear` | `true` = 只清除，不画新的 |

## 用法

```jsonc
plugin_pointer_point({
  circles: [{ x: 1850, y: 38, r: 40, label: "1" }],       // 圈小目标（图标/按钮）
  arrows:  [{ fromX: 1400, fromY: 200, toX: 1600, toY: 80 }],  // 箭头（toX/toY 是**箭尖**）
  rects:   [{ x: 1580, y: 42, w: 120, h: 36, label: "1" }],    // 框较大的目标
  labels:  [{ x: 1200, y: 260, text: "① 先点这里的齿轮" }],      // 自由文字
  duration: 0,        // 等你操作完再消失
  dim: false          // 要读文字就别压暗
})
```

**多个目标一起画** —— 一次调用能画完所有形状，逐条讲步骤时给 `label` 编号。

## 故障模式

### 工具返回 ok 但屏幕没变化

按顺序查：

1. **绘制进程在跑吗** → `curl http://127.0.0.1:<port>/health` 看 `overlayOpen`
   （端口在 GUI 日志里找 `[plugin:pointer-server stdout] PLUGIN_PORT=`）
2. **`reopened: true` 不代表画出来了** —— 它只说明"插件认为该拉起绘制进程"。
   **有没有画出来只能截图确认。**
3. 若 `overlayOpen` 恒 `true` 但没画面 → 状态卡死（已知问题，已修）
4. 若 `reopened: true` 但**没有 render 进程** → server 可能崩了（查 GUI 日志有无 `EPIPE`）

> 详细排查（含进程/端口/日志位置）见 **`plugin_docs name="pointer"`**。

### 画了但用户说"没看到"

- **多半是坐标跑到屏幕外** → 漏加 `monitorOrigin`（多屏时）或漏乘 `pixelRatio`
- 次常见：`monitor` 索引与实际不符（画在另一块屏上）
- 自查：调完**再截一次图**，看指示器在不在目标位置

### 指示器不消失

- `duration: 0` 是**故意不消失**（用于"等你操作完"）→ 用完记得 `clear: true`
