# 坐标换算与多显示器

## 三个坐标系

| 坐标系 | 谁用它 | 原点 |
|---|---|---|
| **虚拟桌面绝对** | `plugin_mouse-keyboard_control` 的 `x`/`y` | **整个虚拟桌面**的左上角（多屏拼接后的原点） |
| **显示器相对** | `plugin_screenshot_region` 的 `region.x/y` | **那块显示器**的左上角 |
| **图内像素** | 你在截图里看到的 | 那张图的左上角 |

**混用它们是点错地方的头号原因。**

---

## 换算（看屏 → 点击）

```
屏幕绝对坐标 = meta.monitorOrigin + 图内像素 × meta.pixelRatio
```

**两个 meta 字段都要用**：

- `meta.monitorOrigin` —— 这张图左上角在虚拟桌面里的坐标
  （对 `fullscreen` 和 `region` 都适用；region 时已是裁切后的原点）
- `meta.pixelRatio` —— **图内像素 → 物理像素**的系数。**1 = 图就是物理尺寸**
  （region 截图、小屏全屏都是这种）。**> 1 表示图被降采样过** ——
  屏幕很大时抓整屏会超过 API 的 2000×2000 图片上限，插件会自动缩小并给出这个系数。

> ⚠️ **漏掉 `pixelRatio` 会系统性偏小**（图被缩过时）。
> 例：2560×1600 屏全屏 → 图 2000×1250，`pixelRatio = 1.28`；
> 图内 x=1000 实际是物理 1280，直接当 1000 用就点偏了。

**`pixelRatio: 1` 时公式还原成 `monitorOrigin + 图内像素`** —— 所以小图场景
不用操心它，但**别假设它总是 1**。

### 单显示器（最常见）

主屏原点就是 `(0,0)`，`monitorOrigin = {x:0, y:0}`，于是：

```
屏幕绝对坐标 = 图内像素 × pixelRatio
```

### 多显示器

假设副屏在主屏**右边**，主屏 1920×1080：

```jsonc
// screen_info 返回
{ "displays": [
    { "id": 0, "x": 0,    "y": 0, "width": 1920, "height": 1080, "isMain": true },
    { "id": 1, "x": 1920, "y": 0, "width": 2560, "height": 1440, "isMain": false }
] }
```

在**副屏**上截的图：`meta.monitorOrigin = {x: 1920, y: 0}`

图内看到按钮在 `(300, 400)` → 要点的绝对坐标：

```
(1920 + 300, 0 + 400) = (2220, 400)
```

**漏掉那个 1920 就会点到主屏的错误位置**（还可能"看起来点成功了"，因为那里也有东西）。

### 副屏在主屏左边

`monitorOrigin.x` 会是**负数**（如 -2560）—— 照样相加，别丢符号。

---

## `region` 的坐标是"显示器相对"

`plugin_screenshot_region` 的 `region: {x, y, w, h}` 里，`x`/`y` 是**相对该显示器左上角**的
（工具内部自己换算成绝对坐标去裁）—— **别把虚拟桌面绝对坐标填进去**。

多屏时若在副屏上截，`region.x` 从 0 开始（副屏自己的左边缘），不是 1920。

## 高 DPI / 缩放

插件已设置 **DPI 感知（PER_MONITOR_AWARE_V2）**，所以：

- 截图返回的 `meta.width/height` 是**物理像素**
- 鼠标坐标也是**物理像素** —— 两者同一空间，**直接相加即可**

### ⚠️ 但**外部工具**量到的坐标不可信（2026-09-20 踩过大坑）

**PowerShell / .NET / 任何 DPI unaware 的进程，读写坐标都是"逻辑像素"**（÷缩放比）。
它们返回 `GetWindowRect` / `Cursor.Position` 看着很权威，**实际是另一套空间**。

**我因此浪费了大量时间**：用 PowerShell 读窗口位置（拿到逻辑坐标），拿它算点击
目标 → 必然点偏 → 又反过来"证实"了「插件坐标偏 1.5 倍」的**错误结论**。
实际三个插件坐标系**本来就是一致的**。

**所以：不要用外部工具测量 GUI 坐标。**

### 正确做法：让**被测对象自己报告**

```python
# tkinter 窗口能拿到权威坐标（同进程、同坐标系）
rx, ry = root.winfo_rootx(), root.winfo_rooty()     # 窗口左上角绝对坐标
cx = rx + BTN_X + BTN_W // 2                        # 目标中心，**同坐标系**
# 用这个值去点击 → 精确命中（窗口状态栏会显示 "命中！点击处 (561,560)"）
```

**通用判据**：
- ✗ 外部工具读 GUI 位置 —— **它自己的 DPI 状态会污染结果**
- ✅ 让被测对象自己报告（`winfo_rootx` / 画出来再截图测 / 直接问接口）
- ✅ 想推断"缩放比例"时**必须多点采样** —— 实测 raw `SetCursorPos`：
  `500→500`、`1000→1000` 都准，`1500→1066` 才被 clamp（**缩放不是逐点除法**）

### 验证"操作是否生效"时，看**对象自己的状态**，别读日志/返回值

实测教训：靶窗口明明在状态栏大字写着"命中"，我却去 `grep` 日志文件（读的是
**上一轮的旧内容**）→ 误判"没点中"。**日志可能滞后、可能属于上一个进程。**

## 快速自检（点之前花 5 秒）

1. 截的图是哪块屏？→ 看 `meta.monitorOrigin`
2. 我在图里量的坐标，加过 `monitorOrigin` 了吗？
3. 这个坐标在屏幕范围内吗？（`0 ≤ x < 屏宽`，超出说明多半算错了）

**第 3 条能挡掉大部分错误** —— 如果你算出的 x=3500 而屏幕只有 1920 宽，那一定是漏加或重复加了偏移。

---

## 拿不准时

- **想要所有显示器布局** → `plugin_mouse-keyboard_control { "action": "screen_info" }`
- **想知道鼠标现在在哪** → 同一个调用的 `mouse` 字段
- **目标很小看不清** → 用 `region` 截目标周围 200×200，坐标立刻清楚
