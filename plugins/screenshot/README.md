# 截屏 (screenshot)

截屏工具：三种模式 + 自动让开位置，截完直接送去该去的地方。

## 做什么

| 能力 | 说明 |
|---|---|
| **全屏** | 抓光标所在的那块显示器 |
| **区域** | 冻结当前画面 → 拖框选择（见下方说明） |
| **窗口** | 移动鼠标到目标窗口上（会高亮），点击截取。Windows 用 `PrintWindow` 直抓该窗口，**被别的窗口挡住也能截到它自己的内容**；macOS 走系统原生点选 |
| **快捷键** | 默认 `Ctrl/Cmd + Shift + X` 触发区域截图（**本应用内生效**，见下方「关于热键」）。可在 设置 → 快捷键 里改 |
| **三个去向** | 插入聊天输入框（`@ref` 引用，点开可预览）/ 发送到超级桌面 / 仅保存到文件 |

默认保存位置是**当前工作区**的 `.claude/screenshots/`（跟粘贴图片的 `.claude/pasted/` 同一惯例，不污染工作区文件树）。可在 设置 → 插件 → 截屏 里改成固定目录。

## 怎么用

1. 按 `Ctrl+Shift+X`（**先在 GUI 窗口里按**）→ 窗口自动最小化让开位置 → 屏幕出现选框 → 拖出要截的区域
2. 松手即自动投递（默认送到聊天输入框），并提示已保存；窗口自动恢复
3. 想换去向：桌面面板里改「默认去向」，或事后在截屏面板里点缩略图重投

**框选时的按键**：`Esc` 取消 · `Enter` 用整屏 · 右键取消

### 关于热键：为什么是「应用内」而不是全局

热键只在**本应用窗口处于前台时**生效 —— 这是刻意的：全局热键是**系统级独占**的
（同一组合键整个系统只能一个程序持有），多开 GUI 时会互相抢，先启动的那个赢、
其余静默失效。改成应用内后，**每个实例都能用、行为一致、不打架**。

代价是截图前要先切到 GUI。但配合下面的「让开位置」这不成问题：切过来时**上一个
窗口还在后面**，让位一让，正好露出它 —— 想截的东西还在那儿。

### 让开位置（默认开）

截图前把 GUI 窗口**自动最小化**，好让出被它挡住的画面；截图完成或取消后自动恢复。

- 想让 GUI 本身出现在截图里 → 设置 → 插件 → 截屏 里关掉它
- AI 调用的截图**由 AI 自己判断**要不要让开（工具参数 `clearScreen`，见下）

> 什么场景需要它：你要截的东西**正好被 GUI 挡着**。没有这个功能时，按热键要求 GUI
> 在前台、而 GUI 在前台又挡着你截 —— 是个死循环。让位把这个环打开了。

## 让 AI 直接截屏（不需要你操作 UI）

这个插件还向 GUI 里的 AI 暴露两个工具 —— **AI 能自己截屏看图**，全程不需要你点任何东西：

| 工具 | 用途 |
|---|---|
| `plugin_screenshot_fullscreen` | 截一整块显示器（默认主屏，可传 `monitor` 指定第几块） |
| `plugin_screenshot_region` | 截指定矩形（物理像素，相对目标显示器左上角） |

两个工具都有个可选的 `clearScreen` 参数：**是否在截图前最小化 GUI 让开位置**。
不传则跟随你的设置，AI 也可以按情况自己决定 —— 它知道你是正在看 GUI（那就别打扰），
还是正需要看 GUI 后面的东西（那就让开）。

**典型场景**：你让 AI「看看这个报错弹窗长什么样」「这个图表画得对不对」，它自己截图去看，不用你截图再贴进来。

**要它能用，需要**：

1. 插件已启用（设置 → 插件），且**工作区已绑定** —— 后台进程只在绑定工作区后才启动
2. AI 会话里**看得到**这两个工具 —— 工具表在会话加载时刷新，所以**装完/启用后要重开会话**（或让 AI 跑 `/mcp-refresh`）
3. Windows / macOS（Linux 未实现，清单里也没声明）

> 截图会**落盘**（默认 `<工作区>/.claude/screenshots/`，与其它截图同一处），
> AI 拿到的是**图片内容 + 路径/尺寸等元数据** —— 它既能"看"，也能在后续对话里引用这个文件。

## 管理已有截图（「截屏」面板）

面板就是截图目录的列表（直接读目录，所以你手工删文件它也会跟着变）。鼠标悬停在缩略图上会浮出四个按钮：

| 按钮 | 作用 |
|---|---|
| **→ 聊天** | 把这张送进聊天输入框（点缩略图本身也是这个） |
| **→ 桌面** | 把这张作为图片块发到超级桌面 |
| **预览** | 开一个**独立浮窗**看原图（缩略图只有 96px 高，表格/代码这类细节得看原图）。浮窗里双击图片可在「适应窗口 / 原始大小」之间切换，也可以直接拉大窗口 |
| **删除** | 删除这张（**要点两次**：第一次变成「确认删除?」，再点才真删） |

要一次清多张：点右上角「**选择**」→ 勾选（或「全选」）→ 「删除选中 (N)」→ 再点一次确认。
`Esc` 或「取消」退出选择模式。

> 删除只作用于**当前截图目录内**的文件，不会碰到别处的任何东西。批量删时若某张
> 正被别的程序占用，只会跳过那一张并告诉你，其余照删。
>
> 为什么删除要点两次而不是弹个确认框：插件面板跑在浏览器的沙箱 iframe 里，
> 原生确认框会被**静默拦掉**（点了没反应），所以这里用「按钮二次点击」代替。

**窗口模式**：把鼠标移到想截的窗口上（会自动框住它、并显示窗口标题），点一下即可。
`Esc` 取消。

> Windows 的窗口截图用 `PrintWindow` 直接向该窗口索取画面，所以**即使目标窗口被
> 别的窗口完全盖住，截到的也是它自己的内容**（不是遮挡物的画面）。代价是少数
> GPU 加速窗口（部分 Chromium 内核 / UWP）会返回全黑 —— 这时会自动退回"从冻结
> 画面裁那块区域"（画面可能被挡，但至少能出图）。

## 区域截图为什么是"冻结"的

点区域截图时，程序会**先把屏幕抓成一张图**，再把这张图铺满屏幕让你框选，最后从这张图上裁。

这么做有两个好处：
- **所见即所截** —— 框选期间屏幕再变（弹窗、视频、切窗口）也不影响结果
- **不需要透明窗口** —— 显示的是不透明位图，避开了透明 + 置顶 + 点击穿透那一堆坑

## 依赖

- **node**（后台进程用）—— 若市场里装了 `nodejs` 插件会用它提供的运行时，否则用系统 node
- 抓屏走**系统自带能力**（Windows 用 PowerShell + .NET / macOS 用 `screencapture`），不下载任何额外二进制

## 权限

- **macOS**：首次使用会弹「屏幕录制」授权。**必须允许**，否则截出来是空白的桌面壁纸。
  若误点了拒绝：系统设置 → 隐私与安全性 → 屏幕录制 → 勾选本应用。
- **Windows**：无需额外授权。

## 快捷键冲突

`Ctrl+Shift+X` 若被别的软件占了（微信/QQ/截图工具），设置 → 快捷键 里那一行会标红「注册失败」——
换个键即可。全局热键是从所有应用手里抢键的，冲突是正常现象，不是坏了。

## 已知限制

- **Linux 未实现** —— 抓屏依赖 Windows 的 PowerShell/.NET 与 macOS 的 `screencapture`，Linux 上两者都没有。
- **跨显示器**：一次只能操作一块显示器（框选窗口与窗口列表都只覆盖光标所在那块）。想截另一块屏，把光标移过去再触发。
- **窗口模式**：只能选**当前可见**的窗口（最小化的、无标题的、系统托盘类的不在列表里）；少数 GPU 加速窗口会退回"屏幕裁剪"（见上）。
