04 Surface Map — All 18 Interaction Surfaces

The VS Code Agent panel contains 8 in-panel surfaces (shown in the 420px sidebar mockup) and 10 overlay/dialog surfaces (shown in detail cards below the mockup).

4.1 In-Panel Surfaces

#01
Session History Collapsible
List of past agent sessions with metadata. Header shows session count + "New" button.
  • Active session: accent bg + accent border, glow indicator
  • Hover reveal: rename, pin, delete actions
  • Search + sort bar on expand
  • Two-click delete confirmation
  • Pinned sessions at top with distinct marker
#02
Messages Stream Filtered
Main conversation feed. Supports user messages, assistant responses, thinking blocks, tool cards, diffs, and permission prompts.
  • All / You / Agent filter pills
  • Lazy history scroll-up (load-more)
  • Scroll-to-bottom FAB with message count
  • Pending permission FAB (pulsing)
  • Token counters + timing per assistant msg
#03
Background Tasks Conditional
Running and completed sub-tasks with progress bars. Only shown when tasks are active.
  • Progress bar per task (accent / green / red)
  • Kill (×) button → kill_task
  • "Clear done" header action
  • Badge: running count / total count
  • Auto-dismiss completed non-error tasks
#04
Plan / Todo Panel Conditional
Task plan from plan_tasks message (IDE PlanTasksMessage). Three-state progress tracking.
  • Done (green check) / Active (accent dot) / Pending (outline circle)
  • Blocked-by warning in --yellow
  • Progress badge: N/M in header
  • Collapsible section
#05
Context Bar Always visible
File references, selection info, and diagnostic counts from the current workspace context.
  • File chips with relative path + remove (×)
  • Selection chip: file name + line range
  • Diagnostic badges: error count (--red) + warning count (--yellow)
  • Natural wrap when overflowing
#06
Selection Preview Collapsible
Inline code preview for the selected text range. Shows error line highlighting.
  • Expand/collapse with chevron icon
  • Line numbers (user-select none)
  • Error line highlighted with --red-bg
  • Font: --font-mono, 11px
#07
Status Bar Always visible
Connection status, permission mode, model selector, context window usage, and quick commands.
  • Connection indicator: green/yellow/red dot
  • Permission mode pill: 5 modes (Default, Accept Edits, Plan Mode, Bypass, Custom)
  • Model selector dropdown
  • Context fill bar: 0–50% green, 50–75% yellow, 75–90% orange, 90%+ red
  • Quick commands dropdown trigger
#08
Input Area Always visible
Compose area with file chip support, toolbar actions, and send/interrupt controls.
  • Contenteditable input with placeholder text
  • File chip inline (--accent-bg, removable)
  • @ button → file picker dropdown
  • / button → slash command autocomplete
  • Structure button → Markdown Editor modal
  • Emoji button → emoji picker grid
  • Send (accent) / Stop (red border, during streaming)
  • Slash command autocomplete on typing /

#16

#17

#18

Bottom-right fixed position. 3 variants: success (--green bg), error (--red bg), info (--accent bg). 3s auto-dismiss with fade. Manual close (×).

06 Layout & Implementation Notes

6.1 VS Code Webview Container

  • Width: 420px (VS Code sidebar standard). Responsive down to ~300px minimum.
  • Height: Scrollable container (sidebar-scroll), 720px mockup height, real height = webview viewport.
  • Scrolling: Thin scrollbar (4px), --border color, transparent track. Only the sidebar content scrolls, not individual panels.
  • Theme switching: Toggle 6 CSS custom properties (--bg, --surface, --surface-2, --surface-3, --fg, --fg-2, --fg-3, --border, --accent, --green, --red, --yellow, --purple). The full file has no hardcoded color values outside the :root block.

6.2 CSS Architecture

  • Single-file approach: All styles in one <style> block for the mockup. For implementation, tokens should be extracted to a shared tokens.css and components to individual files.
  • Naming convention: BEM-like: .panel, .panel-header, .panel-header .label.
  • Transitions: 150ms ease for all interactive states. 300ms for progress bar fills. Toast: 300ms fade in, 3s visible, 300ms fade out.
  • No external dependencies: Pure CSS. SVG icons inline.

6.3 Theme Switching Strategy

  • Define all colors as CSS custom properties in :root.
  • Swap themes by replacing the :root block. In VS Code extension, use body.vscode-dark / body.vscode-light class toggles.
  • VS Code exposes vscode.theme.kind — use the webview's body class to apply the correct token set.
  • Alternatively, VS Code's ColorThemeKind API can dynamically set CSS variables via JS.

6.4 Responsive Behavior

  • At <900px viewport: switch from side-by-side (sidebar + annotations) to stacked layout.
  • At <360px: reduce padding, font sizes remain stable (don't scale down).
  • Overlay modals: max-width 480px, centered in viewport with dark backdrop.
  • Dropdowns: positioned relative to trigger, max-height with scroll for long lists.

07 VS Code Webview Integration

AreaGuidance
Webview creationUse vscode.window.createWebviewPanel() or registerWebviewViewProvider() for sidebar. Set retainContextWhenHidden: true for state persistence.
Theme detectionUse vscode.window.activeColorTheme.kind → set CSS class on webview body. Re-listen on onDidChangeActiveColorTheme.
Font scalingVS Code exposes --vscode-font-size, --vscode-font-family as CSS variables in webviews — use them as fallbacks.
Message passingUse postMessage() / onDidReceiveMessage for all extension ↔ webview communication.
File pickerUse vscode.window.showQuickPick() as an alternative to the custom dropdown for file selection.
State persistenceStore session/plan state in extension's globalState. Webview layer is ephemeral.
Context menuRegister vscode.commands.registerTextEditorCommand for "Ask Agent" on selected text → opens webview with pre-filled context.
